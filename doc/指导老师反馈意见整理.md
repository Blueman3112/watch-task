# 指导老师反馈意见整理与优化方案

> **记录时间**：2026-06-19
> **核心思想**：将单纯的可视化界面提升为“具有生命力的排队系统”。任务如同有机体，随着时间、数量和优先级的变化而动态生长、演进，解决智能手表小屏幕信息展示痛点，增强实战可用性。

---

## 1. 视觉与 UI 极简原则
* **配合页面模块化与极简**：手表屏幕空间有限，除去螺旋主界面外，添加任务、查看详情等配合页面必须采用极简设计（精简文字，多用官方推荐的 Icon 和简洁排版）。
* **红绿双色状态指示**：
  * 🟢 **绿色**：代表正常排队流转、无压力的常规任务。
  * 🔴 **红色**：代表突发紧急任务，或已临近 Deadline 产生警戒的排头任务。

## 2. 螺旋组件的算法演进与交互
* **节点有机生长算法（逐次放大）**：任务节点的大小与优先级/紧急程度强绑定。**越紧急、优先级越高的任务，随着在螺旋线上向外围移动，其节点尺寸会变得越大越显眼**，表现出“逐渐长大”的视觉冲击。
* **运动停止机制（锁死提示）**：当最外圈（即最紧急）的任务进入“红色警戒状态”时，整个螺旋系统的生长/滚动将进入“停滞期”。此机制是在视觉上提示并**强制用户必须优先处理（完成或延期）该高亮任务**，处理完毕后系统方可恢复正常运转。

## 3. 任务的分类、节奏与插队逻辑
* **Demo 预设规模**：为体现系统的容量和排队效果，Demo 中至少需要预设/模拟 11~12 个具有不同关联和优先级的假想任务。
* **三大任务来源分类**：
  1. **手动输入**：用户在手表端直接创建的基础任务。
  2. **外部关联生成**：来自手机日历同步、或每日固定的打卡类任务。
  3. **微信一键导入**：从微信中快速粘贴或同步过来的任务（作为高级功能亮点）。
* **突发任务的插队节奏**：
  * 当有突发任务产生时，该任务将**直接“插队”到螺旋的最外侧（最显眼位置）**。
  * 节点颜色瞬间变为**红色**。
  * 伴随动画效果，将原本排在外侧的其他任务向后（向内圈）挤压排队，完美体现系统的动态响应与节律感。
